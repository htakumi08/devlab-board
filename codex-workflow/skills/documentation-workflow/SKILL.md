# Documentation Workflow Skill

## 基本方針

ドキュメントは、次の状態を目指します。

- 何のためのドキュメントか分かる。
- どこへジャンプすればよいか分かる。
- いつ、どの部分をどう変えたか分かる。
- 複雑な処理や構成が図で追える。
- 未決定事項が本文と分かれている。

## 新規作成

1. ユーザー依頼、既存 docs、実コード、AGENTS を確認する。
2. 設計案、実装メモ、runbook、ADR、workflow のどれかを決める。
3. ファイル名は topic が分かる短い kebab-case にする。
4. 長くなる docs では更新履歴、目次、要確認事項を置く。
5. 図解が必要な場合は Mermaid または text 図を使う。

## 更新

1. 既存 docs の事実と実コードを照合する。
2. 変更対象の章だけを更新する。
3. 既存の表記や粒度をできるだけ維持する。
4. 矛盾がある場合は、古い記述を残さず更新する。
5. 残る未決定事項は要確認へ移す。

## 確認

- 相対 path が正しいこと。
- Mermaid の fenced code block が閉じていること。
- 図の内容と本文が矛盾していないこと。
- 未決定事項がユーザーへ確認しやすい形になっていること。
- `git status --short` で想定外の差分がないこと。
