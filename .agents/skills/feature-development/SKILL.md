# 機能開発

1. `AGENTS.md` と `codex-workflow/README.md` を読み、既存の変更を確認する。
2. [開発ループ](../../../codex-workflow/playbooks/agent-loop.md) に従い、受け入れ条件と最小の縦切りを定める。
3. モデルと担当範囲は開発ループの表に従う。実際にサブエージェントを起動できる場合はモデルを明示し、できない場合は担当を偽らず現在のエージェントが続ける。
4. テスト・ビルド・必要な E2E の結果で受け入れ条件を確かめる。未達なら原因を直して再検証する。
5. 完了時は変更、検証、残リスクを短く報告する。

単純な docs 修正、PR レビュー、設計演習には、それぞれ既存の手順を使う。
