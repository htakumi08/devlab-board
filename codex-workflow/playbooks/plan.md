# 計画プレイブック

1. ユーザー依頼を、devlab-board の具体的な言葉で言い換える。
2. 影響範囲を backend、frontend、infra、docs、workflow に分けて特定する。
3. 推測を避けるために必要最小限のファイルを読む。
4. 作業を順序付きのフェーズに分け、各フェーズの検証方法を明確にする。
5. 前提、リスク、未決定事項を列挙する。
6. サブエージェントを使う場合は、所有範囲と触ってよい path を先に決める。

出力:

- 対象範囲
- 関連ファイルまたはサブシステム
- フェーズ分けした計画
- リスクと緩和策
- 検証手順
- サブエージェント分担がある場合は担当 path
