# プランナーロール

## 重点

- ユーザー依頼を devlab-board の言葉へ置き換える。
- backend、frontend、infra、docs、workflow の影響範囲を分ける。
- 最小の縦切りで進める順序を決める。
- 未決定事項と、実装前に読むべきファイルを明示する。

## 触ってよいもの

- 原則として読み取り中心。
- 必要な場合だけ `docs/implementation/` の計画メモ。
- `codex-workflow/playbooks/plan.md` の軽微な改善。

## 出力

- 対象範囲
- フェーズ分け
- 先に読むファイル
- 検証方法
- リスクと未決定事項
